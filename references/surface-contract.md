# 装饰位图的边界契约

适用于 background / illustration / texture 的 PNG、WebP，SVG 图标不适用。此契约把已有的“容器交给代码、保持原图构图”转换为处理前后的门禁，不能靠一句自然语言决策代替。

## 原图观察 → 清单 → 遮罩

先查看精确源图框及必要的四角/底边局部，填写 `composition.surface`：

```json
{
  "source_frame": "rounded-container",
    "corner_content": "plain",
  "output": "full-bleed",
  "observation": "原卡片四角露出页面底色；水墨画延伸至底部，中间底边是可直接保留的原图。",
  "corner_regions": {
    "top_left": [0,0,4,4],
    "top_right": [28,0,32,4],
    "bottom_left": [0,28,4,32],
    "bottom_right": [28,28,32,32]
  },
  "edge_anchors": [[4,31,28,32]]
}
```

示例仅为 32×32 的合成图，不可复制坐标到业务图片。坐标均相对素材框。

- `source_frame` 为 `none` 或 `rounded-container`。`none` 必须基于实际查看；不可为了跳过检查而把圆角源图声明成 none。
- `output` 固定 `full-bleed`：图片铺满矩形画布，容器在代码中自行裁圆角。不保留卡片边框、阴影、圆角外围页面底色。
- `observation` 记录看见的源图边界和图案触底情况，不填写泛化口号。
- 圆角源图必须使用 repair，四个 `corner_regions` 都存在并接触各自画布角。框只覆盖确需重建的角落；不得扩大到整块艺术图案。脚本检查实际修复遮罩完全覆盖这些框；仅修文字、字迹遮罩未覆盖角落、圆角遮罩继续保护角落，都会被拒绝。
- 每个角可用单个矩形，也可用逐行窄矩形列表近似被容器切掉的弧外楔形，例如 `"top_left": [[0,0,4,1],[0,1,2,2]]`。真实圆弧优先后者；不要因一个角的包围框方便就重绘框内原本可见的艺术像素。相同窄条也须列入 `repair_regions`。
- 截图裁片可能只含原卡片的部分圆角。四个角仍须逐个审视；未被容器裁切的角填 `null`，保留原始像素，不为满足字段人为修复。`rounded-container` 至少有一个非 null 的实际裁切角。
- `edge_anchors` 是原图中应保持不动的干净边缘像素区域，至少一个。必须接触画布边缘、不与任何修复区域重叠；锚点、角落框及背景 `source_ui` 修复区的并集须覆盖整条底边。其余需要保护的艺术细节仍用 `fidelity_regions` 声明。
- 若底边含页面背景中的原模块痕迹，将其纳入 `source_ui` 完整修复，干净锚点移到其他真实边缘。插画整条底边都是容器边框时，重新确定边界或拆分前景；不要虚构锚点或扩大“角落框”绕过门禁。
- 最终画布固定为源框尺寸；原生工具画布按 [canvas-mapping.md](canvas-mapping.md) 受约束回映后再合成遮罩。禁止增加最终高度、补白、任意裁切或改变艺术比例。原生尺寸与最终尺寸分别记录，不宣称原生尺寸一致。

在清单阶段就计算遮罩，确认“要求去掉的部分全部可编辑、要求保留的部分全部受保护”。观察、边界或规格错误应修正对应清单并按正常流程重新审核；不能用同一个错误清单反复生成。

### 背景内部模块

`source_frame` 只描述素材外框。背景另填 `surface.source_ui`，不能用 `embedded_ui: []` 或 `layout_independent: true` 代替源图观察：

```json
{"source_ui":{"observation":"下部有原卡片底色、圆角外沿和投影，需整体重建为连续纸纹。","regions":[{"kind":"module","box":[0,190,462,854]}]}}
```

坐标仅为本案例示意，按当前源图观察填写。`regions` 可含 module / control；box 覆盖完整色块、边框、圆角外围及投影，多模块间有布局痕迹时合并覆盖间隙。确实没有源 UI 时显式填空数组并说明观察。

脚本要求每个 box 全部落入实际可编辑遮罩；圆角内缩、仅去字及漏投影的遮罩拒绝进入生成。已确认无图案的连续区域可整体修复，或使用现有 `background_join` 延伸；后者须在第一个 UI 区域之前完成过渡。不得扩大到主要景物。干净景物/边缘才可作 anchor；底边含 UI 时允许完整修复该段，不能把残留当作必须保留的原像素。

最终记录 `background_ui_regions`，并自动输出原尺寸 `background-module-audit.png`（左侧标记源 UI 范围，右侧为无覆盖的最终底图）。必须查看此图再填写 `module_residue`。原模块范围完全未变时判技术失败；发生变化只说明编辑过，仍须观察每个原模块外沿和整个连续底色。不以色差阈值自动证明没有色块。

## 生成、检查及交付

请求携带 `surface_contract` 及固定载体映射。中间图只供内部检查；优先使用工具已有的静默或仅文件返回选项，不主动转发原生结果，不能把工具直出当作审核结果。宿主自身强制显示的卡片无法由本脚本关闭，不能宣称已隐藏。工具输出经受约束回映后，由执行器仅合成已批准的修复区，其他像素来自原图。最终版本记录 `surface_edge_anchors` 的逐像素结果。

视觉审核额外要求三个独立结论，均包含原图对比的具体观察：

- `container_corners`：逐角检查画面是否延伸到矩形角落；无残留圆弧、页面底色、白角、卡片阴影；补角和原画无接缝。
- `edge_padding`：比较原图与结果的四边，区分原有留白、必要的渐纯过渡、生成新增空带/黑边；不能仅因“尺寸正确”判通过。
- `content_position`：核对山体、舟、花枝等的相对位置和图案触底位置，不能通过缩小主体给留白腾位置。
- 背景另查 `module_residue`：独立底图无原模块色块、圆角边界、投影或接缝；不可只看覆盖了新卡片的首页。实际结果如实记录；用户明确导出已展示效果后不再因此阻断交付。

技术检查失败无法用视觉 passed 或 accept-differences 覆盖。缺少边界契约、当前版本的像素证据或上述视觉记录时，合格交付路径 preview、accept、deliver 均阻断。用户明确导出后则按 export-reviewed 直接导出已展示快照，保留这些检查结果，不要求补齐证据或通过审核。

补角须填写 `corner_content: plain / patterned`。plain 仅用于无图案的纯底色或平滑渐变，脚本以可见边界平滑插值。山水、树木、水面、花枝及可见纸纹属于 patterned，须填 `corner_fill: generated-blend`：编辑工具补绘同风格图案，脚本保留补绘的纹理梯度，按原图边界校色融合。只在已批准楔形内修改，保护区和锚点不变。

禁止逐行/逐列复制、最近邻放大、重复边缘像素或模糊马赛克来冒充图案补全。对 patterned 的 `corner_texture` 单独记录：原尺寸无补块，4倍平滑放大无棋盘、条纹、图案重复或直线接缝；图案尺度和方向与周边一致。不能因尺寸/alpha/保护区检查正确就通过。失败按原两次循环修复，不把 patterned 改为 plain 绕过检查。

内容 QA 使用排除补角区的 content-comparison.png，比较整体构图与主要对象。补角区单独查铺满和接缝，不要求与原图被裁掉的未知画面相同；单个花瓣差异不判失败，新增花束等明显主体变化判失败。排除只由批准的 corner_regions 计算，不能扩大以隐藏主体变化。
