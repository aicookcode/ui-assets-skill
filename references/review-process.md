# 审核与版本

导出前先内部比较候选，为每项挑选一个最优结果，再统一展示；不能把两轮结果全部展示给用户挑选。最终仅展示 review-summary 的 display.md 列出的图片，每项一次；不附其他版本、内部对比图或逐次生成图。顶部说明图标透明、预览底色不属于图标。不显示通过/未通过、修复次数或诊断原因，统一询问“需要修改哪些素材，还是导出当前效果？”。内部质量记录不删除，用户主动询问时再解释。

用户确认节点：描述模式的设计确认、分析后的清单选择、合格结果的集中验收。先给可审核内容，用户已明确批准的步骤不重复确认。

清单修改：保留 ID 与无关结果 → 修改方案并 analysis-check → manifest → 展示完整编号清单 → 用户批准 → approve-manifest。分析第 3 次仍失败时先展示问题标记，等待修改或明确允许继续。

生成检查最多 2 次。结束时执行 review-summary：失败项用 best.json 指定本轮最优候选及比较理由；全部选中项都必须出现在汇总中。按 display.md 内嵌 PNG 与图标的实际预览，每项只展示一个候选，另提供 SVG 链接。用户明确回复“导出”后直接 `export-reviewed` 导出该快照，包括选中的历史候选，不再以检查状态拦截或询问修复。

未明确要求导出时，全部选中项合格后才能正式 preview、accept、deliver，accept-differences 不改变原质量结论。明确导出已展示效果使用独立的 export-reviewed 路径，质量问题保留在报告中，不作为阻断条件。

用户新修改用 revise，仅解锁指定项并开启新的两次处理预算；旧版及无关项保留。改边界、尺寸、方法等需重新分析及清单审核。restore 仅恢复用户指定且与当前规格一致的版本，重新检查与验收；不删除新版。

历史保存于 project.json、analysis、history、candidates、versions。正式包不含失败候选、请求、provider 配置或密钥。
