# 图标透明与紧边界

先核对源框完整，再紧裁输出。查看脚本生成的 `analysis/source-contexts/` 局部：红框是当前源框，周边至少6像素用于观察四边轮廓是否继续。确认屋檐、底座、笔画、阴影均已收全，再填写 `source_edges`；不能只对照同一个可能已裁断的裁片。

声明平色 `matte_background` 的 PNG，分析、清单导入和生产前均检查源框内外连续前景；发现跨框轮廓即拦截并指出方向。按分析循环修正源框后复检，不能靠扩大输出画布、拉伸或补画凑完整。真实源图本身已截断的内容需说明，不能声称已恢复。

此检测只适用于近似平色底，未报错不证明完整。复杂底色、白色前景、SVG及细小柔边仍逐边看周边原图。最终内容框贴边是紧裁的正常结果，不能用它判断源框是否完整。

所有 PNG 图标使用真实 alpha，清单 transparent:true、trim:true。process 自动裁去外围全透明行列，保存 trim_offset；半透明笔画和有效阴影均算内容，不能为了裁紧而阈值删除。预览绿色/浅色底是独立排版层，不能写入素材。

SVG 保持真实矢量。先真实渲染原 SVG，再按绑定的透明渲染收紧 viewBox：

```text
python scripts/icon_bounds.py --svg source.svg --render actual-render.png --vector-sha256 SHA --output tight.svg
```

建议用 16 倍实际渲染求边界。工具只改 viewBox 与画布尺寸，不改路径/描边，写 tight.bounds.json 记录原边界、渲染哈希和偏移。清单的 input_file 指向 tight.svg；process 保存边界证据及偏移。不要覆盖原文件，也不要用原图截图冒充 SVG 渲染。

处理后再次真实渲染 tight.svg，再 render-preview。脚本检查外围透明行列，最多容许 1 个渲染像素的取整差；存在更多外围空白无法进入后续步骤。PNG alpha 内容框须等于文件画布。图标内部空洞不属于外围留白，不能裁掉。

最终汇总将 PNG 和 SVG 一起展示，顶部明确说明底色仅为辨识使用。只给最终效果与名称/编号/格式，不显示内部质量状态；统一询问用户修改或导出。质量检查及源图对比仍在内部执行。
